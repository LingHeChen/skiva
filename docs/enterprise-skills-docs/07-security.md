# 07 · 安全架构、身份与治理

## 1. 信任边界
外部 Git 仓库内容不可信；Webhook 不是无需验证的发布授权；管理前端不可信；挂载客户端运行在相对低信任的机器；CAS 哈希不是访问令牌。Skills 可能携带提示注入内容与可执行脚本，文件签名/哈希只证明完整性不证明业务安全。

## 2. 身份授权
企业生产支持 OIDC (Authorization Code + PKCE)，验证 issuer/audience/签名/过期，服务端自行落实 RBAC、对象级组织过滤。首发部署可用预置单机管理员引导，但生产默认禁止弱口令/无 MFA 的长期管理凭据。客户端建议企业工作负载身份或短期受限令牌；注册/轮换/吊销需审计。

## 3. Git / SSRF
- 仓库 URL 限制 `https`/按需 `ssh`，拒绝 `file://`、本机、本地网段、云 metadata IP，解析 DNS 后再次验证实际连接目标；企业允许私网 Git 时使用显式允许列表，不用全禁私网。
- 限制 Git protocol 的远端重定向和子模块；不自动执行 hooks/filters/CI 自定义命令；有限目录、无 root 权限、资源上限与超时。
- Webhook 使用各供应商标准原始请求体验签、去重和请求大小限制，不把某一个供应商签名规范泛化到所有厂商。

## 4. 内容验证
拒绝绝对路径、`..`、非规范化路径、设备文件、目录外链接。限制文件数、文件大小、总解压/读取量；检测潜在秘钥和高风险脚本；对二进制资源设置可接受类型与大小政策。静态检查仅输出风险，不能声称能完全防止 Prompt Injection。

## 5. API / 存储
TLS；浏览器 Cookie SameSite/HttpOnly/Secure、CSRF 防护（如使用 cookie Session）；CORS 明确域；Rate Limit；Blob 请求授权 snapshot+digest 的对象成员关系。数据库和 Repo 数据卷加密/备份，Secrets 以 KMS/Vault 或受保护 Secret Volume 持有，审计和日志脱敏。

## 6. 发布治理
生产渠道发布权限与仓库写权限分离；核心 Skill 可配置审批人与发布人为不同主体。危险动作确认，reason 必填，产出不可篡改的 channel_history 和追加式 audit_log；审计外送至日志系统以降低数据库超级管理员篡改风险。

## 7. 客户端
秘密最小化；凭据文件权限 0600；不把 SSH/Git 凭据下发；缓存敏感内容使用文件系统权限和可选磁盘加密；拒绝通过文件名泄露其他组织资源；offline policy 配置显式可见。FUSE 进程不以高权限直接解释来源仓库脚本。

## 8. 主要滥用案例
恶意仓库触发 SSRF；手工构造 Git Tree 路径穿越；伪造 Webhook 发布恶意 Skill；读取其他组织 CAS 哈希；短期令牌窃取；断网时权限撤销失效；“已扫描通过”误认为安全；并发发布丢失更新。均需加入测试用例和审计指标。
